Di halaman ini Anda akan membuat permintaan pertama dalam waktu kurang dari satu menit: mengambil tanggal Hijriah hari ini, mengonversi tanggal Masehi ke Hijriah, lalu mencobanya langsung dari kode. ## Tanggal Hijriah hari ini

Kasus penggunaan yang paling umum: berapa tanggal Hijriah hari ini?

```bash
curl "https://api.mabims.dev/api/v1/today"
```

```json
{
  "input": { "date": "2026-08-24", "calendar": "gregorian", "tz": "Asia/Jakarta" },
  "output": { "date": "1448-03-11", "calendar": "hijri", "day": 11, "month": 3, "month_name": "Rabiul Akhir", "year": 1448, "weekday": "Senin" },
  "source": "mabims",
  "warnings": []
}
```

:::tip[Coba sendiri]
Buka [api.mabims.dev/playground](https://api.mabims.dev/playground) untuk mencoba semua endpoint langsung dari browser â€” isi parameternya, tekan **Send**, dan lihat hasilnya.
:::

`today` secara default menggunakan **Asia/Jakarta (UTC+7)**. Anda bisa override dengan zona IANA atau UTC offset apa pun:

```bash
curl "https://api.mabims.dev/api/v1/today?tz=Asia/Kuala_Lumpur"
curl "https://api.mabims.dev/api/v1/today?tz=UTC+8"
```

## Konversi tanggal tertentu

Konversi dua arah. Arah ditentukan lewat param `calendar`:

```bash
curl "https://api.mabims.dev/api/v1/convert?date=2025-01-03&calendar=gregorian"
curl "https://api.mabims.dev/api/v1/convert?date=1446-07-03&calendar=hijri"
```

```json
{
  "input": { "date": "2025-01-03", "calendar": "gregorian", "tz": null },
  "output": { "date": "1446-07-03", "calendar": "hijri", "day": 3, "month": 7, "month_name": "Rajab", "year": 1446, "weekday": "Jumat" },
  "source": "mabims",
  "warnings": []
}
```

Pass `calendar=gregorian` berarti `date` adalah tanggal Masehi dan responsnya berupa tanggal Hijriah; `calendar=hijri` berarti sebaliknya.

Mau lihat hasilnya tanpa menulis kode? Buka [kalender Hijriah MABIMS](/kalender-hijriah/) â€” kalender sebulan penuh, hari penting Islam, dan data hilal dalam satu halaman.

## Selalu periksa `source`

Setiap respons membawa field `source`:

- `mabims` â€” dari data publik Kemenag
- `mabims-computed` â€” dihitung dengan kriteria [Neo MABIMS](https://mui.or.id/baca/berita/mengenal-kriteria-hilal-mabims-standard-penentuan-awal-bulan-hijriyah-pemerintah-indonesia)
- `mabims-retro` â€” di bawah tabel kurasi (butuh `retro=true`): kriteria Neo MABIMS diproyeksikan ke belakang. Kriteria baru diperkenalkan pada 2022 dan data kurasi baru mulai 2023, jadi tanggal sebelum itu adalah ekstrapolasi murni

Kenapa ini penting? Jika `source` = `mabims`, datanya resmi dari Kemenag â€” bisa dipakai tenang. Data kurasi ini diperbarui setiap tahun, biasanya **pertengahan Oktober**. Untuk tanggal lebih dari itu, respons disajikan dari `mabims-computed` â€” dihitung dengan kriteria Neo MABIMS, akurat tapi bukan pengumuman resmi.

Kalau Anda menyimpan hasil API di cache aplikasi Anda, usahakan refresh cachenya **minimal 1x setahun** â€” tepat ketika data `mabims` diperbarui untuk tahun baru.

## `Warnings`

Perlakukan `warnings` sebagai pemberitahuan kepada pengguna apabila ia mengandung payload (tidak kosong).

| Warning | Artinya |
|---|---|
| Date is outside the curated MABIMS table; computed with the Neo MABIMS criteria (moon altitude >= 3 deg and elongation >= 6.4 deg at local sunset, seen anywhere across the coastal observation sites of Indonesia). | Tanggal di luar tabel, dihitung dengan kriteria Neo MABIMS. |
| Hijri month {'{ym}'} is close to the Neo MABIMS visibility threshold; the officially announced date may shift by one day. | Bulan Hijri berada di batas ambang kriteria visibilitas â€” tanggal resmi bisa bergeser Â±1 hari. |
| kemenag_override: 1 {'{bulan}'} {'{tahun}'} H resmi {'{tanggal}'} (Sidang Isbat; kalender terbit Kemenag: {'{tanggal}'}, delta Â±n hari). | Bulan ini dikoreksi lewat Sidang Isbat â€” tanggal resminya beda dengan kalender terbit. Detail: [Sidang Isbat & Koreksi](/isbat-koreksi). |

## Akses & Batas Rate

### Semua reads bersifat publik

Setiap endpoint di `/api/v1/*` bersifat **publik**, tidak perlu API key dan tidak perlu registrasi, untuk memudahkan para developer mengintegrasikannya ke aplikasi / web.

### Akses browser vs server

| Klien | Perilaku |
|---|---|
| Server-side (curl, backend, cron) | Selalu diizinkan, CORS tidak berlaku |
| Browser | Diizinkan dari origin mana pun |

Respons dilayani dengan header CORS yang fleksibel, sehingga aplikasi client-side di domain mana pun dapat memanggil API secara langsung.

### Batas rate & caching

- **CDN edge** (Bunny CDN): 4 request/detik per IP secara terus-menerus, burst 24. Ini adalah batas rate utama â€” sebagian besar permintaan tidak pernah mencapai origin.
- **Origin** (FastAPI): 240/menit per IP sebagai cadangan jika CDN dilewati. Endpoint hilal (`/hilal/info`, `/hilal/viz`) lebih ketat di origin (60 atau 30/jam) karena komputasi berat, namun respons-nya di-cache publik di CDN (`s-maxage=86400`) sehingga edges hanya sekali render per hari.
- Permintaan yang identik dilayani dari cache CDN dan tidak pernah mencapai origin. Dengan jutaan permintaan/hari, origin hanya melihat sekitar satu permintaan per lokasi edge per sumber daya yang di-cache per hari.
- Respons [`/today`](/endpoints/today) membawa TTL yang kedaluwarsa tepat pada tengah malam waktu lokal, sehingga jawaban yang di-cache tidak pernah basi setelah pergantian hari.
