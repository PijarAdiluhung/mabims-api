Mengembalikan tanggal Hijriah untuk "sekarang" di zona waktu yang diminta. Respons memiliki **TTL edge-cache dinamis** yang expire tengah malam, sehingga tidak stale ketika pergantian hari.

<ApiRequest path="/api/v1/today" args="?tz={timezone}&next={true|false}">
  <TestButton path="/api/v1/today" />
</ApiRequest>

## Parameter

| Parameter | Tipe | Wajib | Deskripsi |
|---|---|---|---|
| `tz` | string | tidak (default `Asia/Jakarta`, UTC+7) | Nama zona [IANA](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones) (`Asia/Kuala_Lumpur`) atau UTC offset (`UTC+7`, `+08:00`) |
| `next` | boolean | tidak (default `false`) | Set `true` untuk juga mengembalikan tanggal Hijriah yang mulai berlaku setelah magrib malam ini (setara pemetaan hari sipil berikutnya) |

## Respons

```json
{
  "input": { "date": "2026-08-24", "calendar": "gregorian", "tz": "Asia/Jakarta" },
  "output": { "date": "1448-03-11", "calendar": "hijri", "day": 11, "month": 3, "month_name": "Rabiul Akhir", "year": 1448 },
  "source": "mabims",
  "warnings": []
}
```

Field `input.tz` menampilkan zona waktu yang *terdeteksi sistem* sehingga klien dapat memastikan zona yang digunakan.

## Tanggal setelah magrib (`next`)

Hari Hijriah dimulai saat magrib, jadi tanggal berganti sebelum tengah malam. Dengan `next=true`, respons juga menyertakan objek `next`: tanggal Hijriah yang berlaku **setelah magrib malam ini**.

```bash
curl "https://api.mabims.dev/api/v1/today?tz=Asia/Jakarta&next=true"
```

```json
{
  "input": { "date": "2026-08-24", "calendar": "gregorian", "tz": "Asia/Jakarta" },
  "output": { "date": "1448-03-11", "calendar": "hijri", "day": 11, "month": 3, "month_name": "Rabiul Akhir", "year": 1448 },
  "next": { "date": "1448-03-12", "calendar": "hijri", "day": 12, "month": 3, "month_name": "Rabiul Akhir", "year": 1448, "source": "mabims" },
  "source": "mabims",
  "warnings": []
}
```

Cukup ganti tampilan ke `next` begitu waktu magrib terlewati. API **tidak** menghitung waktu matahari terbenam, jadi tentukan momen magrib di sisi klien Anda. Tanpa `next=true`, field ini tidak ada dan respons tidak berubah.

`next.source` dilaporkan terpisah karena bisa berbeda dari `source` utama bila pergantian hari melewati batas tabel kurasi.

## Error

```json
{
  "error": {
    "code": "invalid_timezone",
    "message": "..."
  }
}
```

| `code` | HTTP | Penyebab |
|---|---|---|
| `invalid_timezone` | 400 | Zona waktu tidak dikenal |
| `invalid_next` | 400 | Parameter `next` bukan `true` atau `false` |

## Perilaku caching

- `Cache-Control: public, max-age=60, s-maxage=<detik hingga tengah malam lokal>`
- Cache miss pada pukul 06:00 di-cache di edge selama ~18 jam; miss pada pukul 23:59 kedaluwarsa tepat setelah tengah malam sehingga tanggal berganti segera.
- Dengan jutaan permintaan/hari, origin hanya melihat sekitar satu permintaan per lokasi edge per hari.
