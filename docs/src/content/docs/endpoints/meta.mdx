Informasi tentang data yang dapat dibaca oleh program.

```
GET /api/v1/meta
```

## Contoh

<Tabs syncKey="code">
  <TabItem label="curl">
    ```bash
    curl "https://api.mabims.dev/api/v1/meta"
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const res = await fetch("https://api.mabims.dev/api/v1/meta");
    const data = await res.json();
    console.log("Coverage:", data.coverage.first, "→", data.coverage.last);
    ```
  </TabItem>
  <TabItem label="PHP">
    ```php
    $response = GuzzleHttp\request('GET', 'https://api.mabims.dev/api/v1/meta');
    $data = json_decode($response->getBody(), true);
    echo 'Coverage: ' . $data['coverage']['first'] . ' → ' . $data['coverage']['last'] . PHP_EOL;
    ```
  </TabItem>
</Tabs>

```json
{
  "version": "1.8.0",
  "data_version": "9f2c41aa7b03",
  "coverage": { "first": "2023-01-23", "last": "2026-12-31" },
  "computed_active": false,
  "computed_months": [],
  "method": "neo-mabims-multisite",
  "docs_url": "https://mabims.dev",
  "hilal_image_range": [1444, 1475],
  "divergences": [],
  "table_version": "none"
}
```

| Kolom | Deskripsi |
|---|---|
| `data_version` | Hash pendek dari tabel MABIMS yang berubah ketika tabel diperbarui |
| `coverage` | Rentang Masehi yang tersedia di tabel rujukan |
| `computed_active` | `true` setelah ada permintaan yang menggunakan hasil perhitungan Neo MABIMS |
| `computed_months` | Daftar bulan yang sudah dihitung dengan kriteria Neo MABIMS |
| `method` | Metode perhitungan di luar tabel (`neo-mabims-multisite`) |
| `hilal_image_range` | Rentang tahun Hijriah `[min, max]` yang gambar `/hilal/viz` dan `/hilal/map`-nya sudah dibuat lebih dulu; di luar rentang itu gambar dibuat saat diminta |
| `divergences` | Riwayat koreksi Sidang Isbat. Setiap entri berisi `hijri_month` (bulan yang dikoreksi) dan `delta_days` (jumlah hari pergeseran). Kosong jika belum ada koreksi |
| `table_version` | Penanda versi riwayat koreksi. Nilainya `"none"` jika belum ada koreksi dan berubah setiap kali koreksi diterapkan. Bandingkan dengan nilai yang tersimpan untuk mengetahui kapan data perlu diambil ulang |

## Saran untuk klien

1. Periksa `/meta` setiap hari. Permintaan ini ringan dan hasilnya dapat disimpan di cache selama 5 menit.
2. Jika `computed_active` bernilai `true`, tampilkan pemberitahuan di antarmuka Anda. Tanggal hasil perhitungan dapat berbeda ±1 hari dari pengumuman resmi.
3. Bandingkan `table_version` dengan nilai yang tersimpan. Jika berubah, periksa `divergences[]` dan ambil ulang tanggal pada bulan yang dikoreksi. Lihat [Sidang Isbat dan Koreksi](/isbat-koreksi).

## GET /healthz

Pemeriksaan singkat untuk memantau apakah layanan masih berjalan.

```
GET /healthz
```

<Tabs syncKey="code">
  <TabItem label="curl">
    ```bash
    curl "https://api.mabims.dev/healthz"
    ```
  </TabItem>
  <TabItem label="JavaScript">
    ```js
    const res = await fetch("https://api.mabims.dev/healthz");
    const data = await res.json();
    console.log(data.status); // "ok"
    console.log(data.build_hash); // "a3f8c1e2b4d6f7a8"
    ```
  </TabItem>
  <TabItem label="PHP">
    ```php
    $response = GuzzleHttp\request('GET', 'https://api.mabims.dev/healthz');
    $data = json_decode($response->getBody(), true);
    echo $data['status']; // "ok"
    echo $data['build_hash']; // "a3f8c1e2b4d6f7a8"
    ```
  </TabItem>
</Tabs>

```json
{
  "status": "ok",
  "version": "1.8.0",
  "build_hash": "a3f8c1e2b4d6f7a8"
}
```

Mengembalikan header `Cache-Control: public, max-age=10`.
